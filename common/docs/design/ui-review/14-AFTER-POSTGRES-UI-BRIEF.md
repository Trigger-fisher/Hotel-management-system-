## A. Calm motion: nothing moves for decoration
**Rule:** an element may animate only to show a change the user caused (hover, focus, press on a BUTTON, a panel opening, a value that just changed). Never on load, never forever, never to "feel premium". Pallav's own subtle transitions are the ceiling, not the floor: tokens `--dur-micro 120ms`, `--dur-base 220ms`, `--ease-out cubic-bezier(.16,1,.3,1)`; `prefers-reduced-motion` turns even those off.

| Item | Decision |
|---|---|
| Springs (Reanimated spring, overshoot easing `--ease-spring`) | REMOVE everywhere. Use 120-220ms ease-out, no overshoot |
| Shimmer sweep on skeletons | REMOVE. Use a static soft block (no movement); Pallav dims the list while loading (`.is-live-loading`) and shows a small spinner in the search box: copy that |
| Slide + fade page transitions (12px slide on push/back) | REMOVE. Pages swap instantly (or a 120ms fade at most); no slide |
| Press scale on every row/card (0.98/0.94 opacity) | REMOVE from rows/cards. Keep only Pallav's own `.btn:active { scale .97 }` on real buttons |
| Mobile diamond: rotation, plus -> x turn, spring open | REMOVE rotation and spring. The diamond stays (MJ) as a static raised button; its sheet opens with a 120-180ms fade; icon stays a plus |
| Dock indicator slide, icon lift/scale | REMOVE motion: active tab changes colour/pill instantly (Pallav's 220ms colour transition is fine) |
| Collapsing large title, header title cross-fade | REMOVE. One fixed page title in the top bar like Pallav |
| Empty-state halo spring-in | REMOVE: static icon block |
| Haptics | keep light selection feedback only on tab change and diamond press (not motion); respect OS setting; nothing on toasts |
| Pallav's own DECORATIVE motion: sidebar blobs drifting (23-27s), user online-dot ping, logo sheen sweep, button sheen sweep, KPI hover lift -3px + corner blob growth, sidebar entrance (`sb-intro`) | MJ said nothing that moves for decoration, and these ARE Pallav's. Decision (Reviewer, for the Lead to confirm with MJ): build them **static** (blobs fixed, dot solid, no sheen, no entrance); keep hover lift only on buttons (-1px) and KPI tiles (-3px) because it answers the user's pointer; mobile has no hover so nothing. If MJ wants them exactly as Pallav, flip a single token `--motion-decor: 0|1` |
| Chart/number animation | no count-up, no bar grow-in |
| Acceptance | a reviewer with a screen recording sees no movement while the user does nothing; reduced-motion run shows zero transitions |

## B. Day / night toggle (replaces "night follows the device only, no toggle")
Truth = Pallav (`layouts/app.blade.php`, `pms-ui.js`, `pms-dark.css`): `<html data-theme="light|dark">`, set before first paint; saved key `pms-theme` in **localStorage per browser**; if nothing saved, the **device preference** (`prefers-color-scheme`) decides; a **moon/sun button in the top bar** toggles between exactly two states (icon `bi-moon-stars` in day, `bi-sun` at night, tooltip "Switch to night mode / day mode"); no third "Automatic" choice exists in Pallav. **Decision:** copy that exactly (two states, device default on first visit), with one improvement MJ asked for: **remembered per user**, not only per browser.
- Storage: user preference `ui_theme` (`light` | `dark` | null = follow device) saved through the profile (non-credential preference; Worker B's Admin/profile endpoint `PATCH /api/v1/profile/preferences`, audited? no, plain preference). Client keeps a local copy to avoid a flash and writes it on toggle; on sign-in the server value wins on every device.
- Web: the same inline pre-paint script (no flash), button in the top bar. Mobile: the same button in the top bar (or in More/Profile if the bar is full), applies at once, persists locally + server.
- Night values: **Pallav's `pms-dark.css` is the truth**, replacing the palette I derived: page `#0D0A14`, surface `#15111F`, surface-2 `#1B1628`, line `#261F38`, line2 `#33294B`, accent `#7C3AED` (hover `#6D28D9`), accent-ink `#C4B5FD`; solid tints for icon tiles (violet `rgba(139,92,246,.18)` text `#C4B5FD`, green `rgba(16,185,129,.16)`/`#6EE7B7`, amber `rgba(245,158,11,.16)`/`#FCD34D`, red `rgba(244,63,94,.16)`/`#FDA4AF`); no gradients, no glow, KPI corner blob hidden; sidebar `#151024` family. I will check the contrast of each text/background pair and report any that fail AA as the only allowed deviations (same rule as day mode).
- Tests: toggle persists across reload and across devices (server value), first visit follows the device, no flash, both modes snapshot-checked per screen group.

## C. Smart search bar (top bar, web + mobile)
Pallav already has in-list smart search (`pms-live.js`: prediction dropdown with bold matches, recent searches, inline completion, `/` focuses the page's box, no reloads) and no global search. We add ONE global search with the same look (Pallav `.pms-predict` dropdown, `.search-field`).
- **Web:** wide search field in the top bar (placeholder "Search screens, companies, customers, staff, bills..."), shortcut `/` and `Ctrl+K`/`Cmd+K`, typeahead after 2 characters, 150ms debounce, arrow keys + Enter + Esc, results grouped under small uppercase headings (SCREENS, COMPANIES, CUSTOMERS, STAFF, BILLS, RESERVATIONS, ROOMS), each row = icon tile + title (typed words bold) + one hint line (code, date, amount) + the Pallav chip for status; empty box shows **Recent** (last 8 opened results, per user, local + server) and "Go to" shortcuts; no results: "Nothing found for X" + the closest screen. Enter opens the first result; opening a record goes to its view page; role-aware: a type the user cannot VIEW never appears.
- **Mobile:** a search icon in the top bar opens a full-screen sheet with the field focused and the same groups; recents on open; the keyboard "Search" key opens the first result. No hardware shortcut.
- **Screens group:** client-side from the role's navigation registry (already permission-filtered), fuzzy on title and keywords ("deposit" -> Revenue), so it works offline and costs no request.
- **Backend need (one endpoint, Worker B after Admin core, on the in-memory doubles first):** `GET /api/v1/search?q=&types=&limit=` (default 8 per type, hard cap 50 in total, q length 2-64, strict zod, no wildcard characters from the user). It fans out to the existing per-module lookup repository methods (companies, customers, staff, bills, reservations, rooms, stays) inside ONE `withHotel` unit; each type is included only if the session has `view` on that module (permission-aware; group/platform admins use the audited path); returns `{data:{groups:[{type, items:[{id,title,hint,href,status?}]}]}}`. Rules: tenant-scoped by `withHotel` (nothing cross-hotel), never returns sealed fields (phone, Aadhaar, bank): a phone/GSTIN/PAN search only matches the blind index and shows the last 4 only; soft-deleted rows hidden (except the recycle bin ability, which sees them under a "Deleted" tag); rate limit per session (for example 20/min); `Cache-Control: no-store`; same case-insensitive semantics as Pallav (parity tests with the 87 golden searches for the types that overlap); Postgres: `lower(name)` / `pg_trgm` GIN indexes on name, code, bill number, company name (Backend 1 adds in the module migrations), prefix match first then substring, ranked by exact > prefix > word start > substring. Tests: permission matrix per role, isolation (hotel B names never appear), limit, hostile input, performance budget (p95 < 150ms on a 100k-row hotel on the load test).
- **Recents:** `search_recent` per user (type, id, label, opened_at, keep 20) behind the profile preferences endpoint; localStorage mirror.
- **Acceptance:** keyboard-only use works, screen-reader announces result count and selected item (combobox/listbox pattern), reduced-motion safe (no animation at all per A), works at 320px, both themes.
