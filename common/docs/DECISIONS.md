## What we are building
The **entire Hotel Pallav Laravel account system** (GitHub `Mihir-Jungiwala/hotel-pallav-account`) moves into HMS as a **single-page web app (Next.js)** (**no mobile app** in the pilot), with **nothing changed in behaviour**. Three dashboards: **Hotel** (everything staff use), **Guest** (Pallav's guest portal) and **Corporate** (Pallav's company portal). Multi-hotel: each hotel's data is separate.

## Design
1. The UI must be **100% the same as Hotel Pallav**: layout, colours, fonts, sizes, spacing, icons, tables, forms, pills and wording, and **the same pages and menu** (order and names). "Premium" means polish inside Pallav's look, never a new look.
2. **Day AND night mode** both match Pallav (Pallav's own `pms-dark.css`). A visible day/night switch (Pallav's moon button) remembered per user (server preference `uiTheme`: light, dark or null = day). MJ, 5 Nov 2026: the app and the sign-in screens always open in day and never follow the device; night only by the person's own switch.
3. **Calm motion**: nothing animates for decoration. Only Pallav's own subtle transitions; hover lifts 1px on buttons and 3px on KPI tiles.
4. **Smart search bar** in the top bar (`/` or Ctrl+K), server endpoint `GET /api/v1/search?q=`.
5. Web approach: Pallav's own CSS (vendored in `web-app/public/pallav/`) plus **Bootstrap 5.3.3**, Bootstrap Icons, flatpickr, Tom Select (all MIT, local files, loaded only on the dashboard). Each screen is written in React with Pallav's own markup and class names, one Blade view = one TSX file. Guide: `docs/UI.md` (the one UI document).
6. **NO MOBILE APP in the pilot** (MJ, 06 Oct 2026). The Mobile App/ folder and every mobile-only file were deleted (git history still holds them: commit before Remove mobile app). The product is the web app only; screens must still work at phone width (Pallav's own responsive layout).
7. Sign-in: Pallav's login (username/email + password + emailed 6-digit code for admins, temporary password must be changed at first sign-in, 5 wrong passwords lock 15 minutes). **ONE sign-in page for every person**: the field is "Username or email" (both unique); the app opens the person's own dashboard by role. Forgot password by emailed code. Sessions: 120 minutes idle on the web, 90 days on a phone.
8. Auth readability fixes kept (muted text #5E5775, copyright 72% white, primary button gradient p600 to p800); input 42px/14px (16px on phones only), button 44px/14.5px, resting border #D9CEF6, all Pallav's measured values.
9. Rupee grouping is ONE central switch `MONEY_GROUPING` in `ui-shared/dashboards/format.ts` (default `western` = Pallav's 126,000.00; `indian` = lakh style). **Open question for MJ.**

## Database and security
10. **PostgreSQL 18 is FINAL** (no more switching). HMS's OWN instance on `127.0.0.1:5433` (never the other Postgres install on 5432 with the lost password). One database `hms`; one **schema + one login-less role per hotel** (`hotel_<32hex>`); app role `hms_app` switches role per request (`SET LOCAL ROLE`); hotel A cannot read hotel B (proven by tests). MySQL, SQLite and Supabase were considered and rejected.
11. **No encryption of stored data and no keys for MJ to set up**: plain columns; account numbers, ID numbers, IFSC, emergency numbers come back in full (as Pallav shows). Passwords stay **hashed**. Integration secrets (SMTP, Razorpay, Google, backup) are stored plain but **never returned by any API** (only `set: true|false`). All secrets the system needs are generated by scripts into `.env.local`. Risk note: `docs/BACKEND.md` section 5.1.
12. **Pallav's data import is CANCELLED.** New hotels start empty. Pallav's own MySQL install and data are never touched or deleted.
13. Money is stored in **paise**. Dates `04 Oct 2026`, 12-hour IST times. GST: typed percent 0 to 28, hotel default 5 and food default 5 (two settings), percent saved on each bill. Hotel and food GSTIN are hotel settings printed in bill and advance-receipt headers.
14. Pallav quirk (a) fixed: a debit side owes its total less the advance, never below zero. Quirks (b), (c), (d) are kept as Pallav has them.
15. A **version check** ("someone else changed this, please refresh") on every save of records that two people can edit, including salary payments (`SalaryRecord.version`). Stale = CONFLICT with `details.currentVersion`.
16. **PDFs always**: every printable document opens as a real PDF (engine `pdfkit`, one DocumentRenderer, fonts Inter and Noto Sans Gujarati/Devanagari); emails carry the PDF. 13 routes exist (`PDF_ROUTES` in `ui-shared/dashboards/common.ts`); more are agreed but not built.
17. Paging: phones 10 per page; allowed sizes 10, 25, 50, 100. Statements are one call per period, capped at 5,000 rows. Pickers use a typeahead lookup capped at 50.
