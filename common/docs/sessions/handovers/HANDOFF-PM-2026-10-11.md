## 7. The push procedure (do exactly this)
1. `git fetch`; check `git rev-list --left-right --count main...origin/main` and `git status --short` (uncommitted files belong to working sessions: never commit them, never push them).
2. Make a clean copy of the committed HEAD: `git worktree add --detach C:\Users\jungi\AppData\Local\Temp\<name> HEAD` (absolute path without spaces); a Junction for node_modules breaks Turbopack, so `robocopy` `web-app\node_modules` and `pathik\worker\node_modules` into it.
3. In `<copy>\web-app`: `npx next typegen`, `npx tsc --noEmit -p tsconfig.json` (expect 0), `node scripts/check-shared.mjs` (expect total 0), `node --test tests/*.test.ts`, `npm run test:server` (expect 0 fail), in `pathik\worker` `npm test`, then `npm run build` (expect exit 0). Use generous timeouts (up to 10 minutes) and run long steps separately.
4. If green: `git push origin main` from the real folder; `git worktree remove --force <copy>`; `git worktree prune`.
5. Secret scan of the pushed diff (grep for password, token, key, postgres:// with a password): only test fixtures are acceptable.
Quirks: PowerShell `Remove-Item` on paths containing a space can be blocked by the guard (use absolute paths without spaces, `-LiteralPath`); .NET file APIs resolve relative paths from a different working directory (always use absolute paths); `tar` cannot read `git archive` output on this PC (use worktrees); starting `pg_ctl` in a piped command can hang (start and query in separate commands).
