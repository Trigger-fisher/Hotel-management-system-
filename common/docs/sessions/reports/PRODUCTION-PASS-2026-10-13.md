## 2. What you must do (nothing else works without it)

1. **Neon SQL, in this order:** `docs/neon-sql/NEON-SQL-0118-OUTBOX-HOTEL.sql`, then `docs/neon-sql/NEON-SQL-0119-OUTBOX-DAILY-SUMMARY.sql`, then `docs/neon-sql/NEON-SQL-0120-ANNOUNCEMENTS.sql`, then `docs/neon-sql/NEON-SQL-0121-OUTBOX-CAMPAIGN.sql`, then `docs/neon-sql/NEON-SQL-0122-HOTEL-BACKUPS.sql`, then `docs/neon-sql/NEON-SQL-0031-GUEST-REQUESTS.sql`, `docs/neon-sql/NEON-SQL-0032-EMAIL-MARKETING.sql`, `docs/neon-sql/NEON-SQL-0033-PATHIK-RUNNER.sql`, `docs/neon-sql/NEON-SQL-0034-LOG-SUBJECT-INDEX.sql` and `docs/neon-sql/NEON-SQL-0035-PORTAL-RLS.sql` (hotel migrations: each loops over every live hotel; 0035 after `npm run test:db` on the dev database). Each file says what to check before and after. Until 0118 runs, mail still goes through the platform sender; until 0119, the daily summary cannot be queued; until 0120, the Announcements page answers an error.
2. **Vercel:** make sure the project deploys `main` with root directory `web-app` (the production site was still on an older commit when I checked). Set `CRON_SECRET` (32+ random characters) so the daily summary and the mail cron work; optionally `HMS_ALERT_WEBHOOK` (a Slack/Discord/Teams webhook) to get error alerts.
3. **Per hotel, in Settings > Email:** the SMTP host, port, login, from address; press "Send a test email"; then fill "Daily summary to".
4. **Pathik on the live site:** in Vercel set `HMS_PATHIK_RUNNER=online`, `PATHIK_ALLOW_REAL=yes`, `HMS_PUBLIC_URL=https://www.easyhotelsolutions.in` (CRON_SECRET is already there), check Fluid compute is on, redeploy; per hotel Settings > Pathik > Submit = Automatic; stop the PC worker; then press Run now on the Pathik page with you watching. Steps and the "what the card says" table: `docs/pathik/PATHIK-ONLINE.md`.
